# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ESPHome-прошивка для ESP8266 (D1 mini) — шлюз между Home Assistant и самодельной системой умного дома на общей текстовой шине (UART 19200, вероятно RS-485). Роль контроллера играет модуль реле 1 (модуль 2 подключён к нему отдельной линией). Документации на систему нет: протокол восстановлен по программе со старой Raspberry Pi и по записям трафика. Полное описание протокола, таблица кодов клавиш и список неизвестного — в [README.md](README.md); при изменении поведения обновляйте его.

## Команды

Тестов и линтера нет — проверка = валидация конфига и сборка.

```bash
esphome config esphome-gauhartas204-esp8266.yaml                  # валидация
esphome compile esphome-gauhartas204-esp8266.yaml                 # сборка
esphome run esphome-gauhartas204-esp8266.yaml --device <IP> --no-logs   # сборка + OTA
esphome logs esphome-gauhartas204-esp8266.yaml --device <IP>      # логи (только по сети)
```

Лямбды в YAML — C++; ошибки в них видны только на `compile`, не на `config`.

## Архитектура

Почти вся логика — в одном файле `esphome-gauhartas204-esp8266.yaml`:

- **`components/uart_read_line/`** — внешний компонент: только режет поток UART на строки (до 30 символов) и публикует их в text_sensor `latestSerial`. Никакого разбора протокола в C++ нет.
- **Лямбда `on_value` у `latestSerial`** — весь разбор протокола. Ветки: `*RA <модуль> p0…p7 $` (состояние реле; порт N в позиции `6 + 2·N`; ровно 8 значений) → `publish_state` у `uart`-switch'ей; `*RK WM <X>$` → клапан + text_sensor «Состояние модуля воды» (ON/OFF/ALR/WSD/LOW — единственное место, где видны ALR, WSD и LOW); `*RK <модуль> <код> <0|1> $` → подсветка клавиш (только отметка «контроллер жив»); `*10XXYY$` → нажатие клавиши → `event`; `*WM ON$/OFF$` → событие выключателя воды; остальное → `latestSerialUnknown`.
- **Нажатия выключателей**: код `10XXYY`, `XX` — номер выключателя, `YY`: `01`/`04` — короткое верхней/нижней, `02`/`05` — двойное, `03`/`06` — долгое (контроллер реагирует только на короткие и на `…06` у выключателей 1002/1004). Таблица `switches[]` в лямбде сопоставляет `XX` с event-сущностью `switch_10XX` и типами событий коротких нажатий; у каждой event-сущности `event_types` должны содержать все типы, которые ей передаются (иначе `trigger()` отбрасывает событие). Новая клавиша/выключатель = строка в `switches[]` + event-сущность + строка в таблице кодов README.
- **Опрос статуса** (`interval: 3s`): для каждого источника (`*1 STS`, `*2 STS`, `*WM INF`) запрос уходит через 120 с после последней активности по нему — `status_activity_millis[i]` обновляется и ответом (ветки `*RA 1`/`*RA 2`/`*RK WM`), и самим запросом; не больше одного запроса за тик. Первый опрос после загрузки делает тот же interval (значения нулевые).
- **Подсветка клавиш** — скрипт `send_backlight(codes, state)`; его вызывают API-действие `set_backlight` и кнопки «Подсветка: включить/выключить всё» (они передают пустой список — это значит «все клавиши квартиры», список выключателей лежит в самом скрипте). Пишет кадры `*RK 1 <код> <0|1> $` одной строкой (выключатели делят поток по `*`/`$`, перевод строки между кадрами не нужен; несколько кодов в одном кадре не работают); выключатели слушают шину сами.
- **Комнаты** — `esphome.devices`/`areas`; каждая сущность привязана `device_id`.
- **Датчик протечки** живёт в HA: `binary_sensor: platform: homeassistant` подписывается на него через API (у этой платформы `internal` по умолчанию `true` — без явного `internal: false` сущности не видно) и при срабатывании шлёт `*WM ALR$`. Тревога защёлкивается: вода откроется только по `*WM ON$`.

## Особенности шины, которые легко упустить

- В API уходит только **печатный ASCII**: компонент заменяет прочие байты на `?`. Помеха на шине давала невалидный UTF-8 в `TextSensorStateResponse.state`, из-за чего клиент (HA, `esphome logs`) обрывал соединение с `UnicodeDecodeError`.
- ESP **не слышит собственные передачи**: отправленные команды не появляются в `latestSerial`, судить о результате можно только по ответу контроллера (`*RA`, `*RK`).
- Контроллер сам присылает `*RA` затронутого модуля (~0,25 с) после любого переключения — и от HA, и от физической клавиши. Нажатие «выключить всё» присылает оба модуля.
- Контрольных сумм и арбитража нет; проверки кадра в лямбде (`*…$`, длина) — единственная защита от мусора.
- Нажатие физической клавиши можно имитировать, отправив её код в шину (text-сущность «UART команда», `\r\n` добавляется сама) — так проверялись отсутствующий выключатель 1004 и коды `…06`.

## Проверка на живом устройстве

- UART0 занят шиной (`logger.baud_rate: 0`); логи только по сети, и ESP8266 **теряет строки лога** при всплесках. Для проверки надёжнее SSE-поток веб-сервера: `curl -N http://<IP>/events`.
- REST веб-сервера v3 (путь включает имя устройства-комнаты, URL-кодировать): `POST /switch/Прихожая/LobbyLight/turn_on`, `POST /text/Управление/UART команда/set?value=...`.
- API-действия вызываются через `aioesphomeapi` из окружения ESPHome (`APIClient(host, 6053, None)`, `execute_service` — корутина).
- Локальная сборка имеет версию `dev`, поэтому HA предлагает «обновление» до последнего релиза — его установка откатит прошивку.

## Релизы и OTA

- `esphome.project.version: dev` заменяется на тег релиза `sed`-ом внутри `esphome/workflows` build — строку `version: dev` не менять.
- Устройства берут OTA-манифест из **корня** GitHub Pages (`update.source` → `/manifest.json`); `publish-pages.yml` строит его `jq`-ом из манифеста релиза, добавляя `firmware/` ко всем путям (`ota.path` и `parts[].path`, чтобы он годился и для esp-web-tools). Уже установленные устройства опрашивают этот URL — не переносить.
- Релизы собираются на ESPHome `stable`, CI — на `stable` и `beta`.

## Соглашения

- Имена сущностей (`LobbyLight`, `SleepingroomWardrobe`, …) и `id` не переименовывать без необходимости — на них завязаны entity_id и автоматизации в HA; комнату меняют через `device_id`.
- Секреты (ключ API, пароли OTA/AP) в конфиг не добавлять: прошивка релизов публичная. Это осознанное решение владельца.
- Комментарии и документация — на русском.
